# Проверки живого AI Studio

14 ноября 2026 года, предварительная проверка этапа 4.

Во встроенном браузере пользователь выполнил вход. Открыты два тестовых чата
с одинаковым общим шаблоном `Helper protocol acceptance`. Маркер передавался
видимым блоком в первом обычном запросе. В каждом чате выполнен один запрос
и получен один ответ. Отдельных сообщений согласования и исправления не было.
Модель вернула соответствующий 32-символьный маркер в начале и конце ответа.
Второй ответ содержал точное тело `second-tab`. После перезагрузки первого
сохранённого чата его маркер и ответ сохранились.

Обнаружено склеивание строк пользовательского контекста в textContent.
Чтение маркера переведено на текстовый prompt-chunk с учётом BR.
Воспроизведение реального заголовка User и BR добавлено в Chrome-стенд.

Общий шаблон был настроен в каждой вкладке. Автоматическое появление сохранённого
preset во второй вкладке не подтвердилось. Код отделяет маркер от preset,
а проверка именно установленного расширения и его автоматической настройки
остаётся частью итоговой приёмки этапа 11.

В первом запросе естественное описание текста включало завершающую точку.
Модель передала кавычки и буквальный обратный слеш, но опустила точку.
Это семантическая неточность ответа, которую парсер не может восстановить
однозначно. Для точных данных требуются проверенные источники и предусловия.

Эта проверка подтверждает способ передачи контекста и наблюдаемый DOM.
Сквозная работа установленного расширения, агента, Gate, вложений,
переподключения и отката проверяется на этапах 10–11.

## Этап 11, прямой маршрут, 14 ноября

Установленное расширение 0.4.0 подключилось к локальному агенту
1.5.0-ai-studio-alpha.7 без настроенного Gate. В сохранённом чате AI Studio
модель вернула v2-вызов `read_file` с маркером текущего чата. Агент выполнил
одно чтение тестового UTF-8 файла с BOM, CRLF, кириллицей и emoji, 35 байт.
Полученный результат и его SHA-256 сохранились после перезагрузки расширения.

Штатный загрузчик AI Studio принял `read-me.txt`. Пользователь подтвердил первое
окно copyright acknowledgement. После отправки подготовленного результата
штатной кнопкой Run модель прочитала вложение и вернула точный текст
`Live acceptance Привет 😀`. Автоматических запросов исправления модели — ноль.

При приёмке исправлены распознавание `Run Ctrl`, ошибочное принятие кнопки
`Remove Grounding` за вложение, закрытие System instructions после вставки
и повторное продолжение собственного неизменённого черновика. Последнее
проверено в Chrome с подсчётом событий загрузки, повторной передачи файла нет.
Ручная отправка уже подготовленного результата распознаётся по операции в истории
и подтверждается без нового Run и нового вложения.

По просьбе пользователя добавлено автоматическое подтверждение известного окна
`copyright-acknowledgement-dialog` единственной кнопкой
`Agree to the copyright acknowledgement` во время разрешённой загрузки файла.
Chrome-стенд проверяет подтверждение, отмену и сохранение других диалогов.
Повторное появление этого окна в живом аккаунте после принятия условий
пока не наблюдалось. Произвольные модальные окна требуют отдельного обработчика.

Полный автоматический цикл повторного чтения прошёл на чистой сборке `c437dfa`
после перезапуска агента с сохранением журнала. Расширение загрузило файл,
отправило результат и дождалось точного ответа модели. Старый вызов повторно
не исполнялся. Новый чат выявил вложенный `ms-system-instructions` внутри
внешнего `mat-dialog-container`, чей крестик находится снаружи дочернего блока.
Поиск поднят до внешнего окна, оба варианта его роли проверяются в Chrome.

Новый чат на `c77f022` подтвердил автоматическое закрытие окна. Следующая
живая проверка записи выявила отдельный обработчик Run в content-скрипте,
который не распознавал подпись `Run Ctrl`. Из-за этого маркер не добавился
к первому запросу, и модель отказалась выполнять инструменты. Вызовов и записи
файла не было. Распознавание Run объединено с адаптером, проверка content-скрипта
теперь использует ту же функцию и проверяет добавление маркера до первого Run.

На исправленном обработчике первый запрос нового чата получил свой маркер.
Модель записала файл с кириллицей, emoji, буквальными обратными слешами,
кавычками и HTML-символами. Независимая проверка подтвердила точные 50 байт,
три строки без завершающего LF и SHA-256
`a9bd567b90acae58cfc1b7d3096df199c8a8a62bdfb152d5545866b084860e95`.
Запись выполнена один раз. Первый `Get-FileHash` завершился ошибкой отсутствующего
модуля PowerShell. Модель получила настоящую ошибку инструмента, затем новая
команда с импортом штатного модуля завершилась кодом 0 и подтвердила хеш.
Результаты передавались автоматически. Запросов исправления формата — ноль.

Чистый EXE `9810165` запущен с прежним журналом. Старый результат чтения
восстановлен по исходному ID. Для живой проверки потери ответа использовался
локальный тестовый HTTP-посредник, Gate не запускался.

- Обрыв TCP после принятой записи вызвал прозрачный повтор POST в Chrome.
  Два одинаковых запроса создания дали один фактический `write_file`.
- HTTP 503 после принятой записи дал один запрос создания и одно чтение
  `operations/lookup` с тем же ключом. Повторного создания не было.
  Плагин восстановил результат, передал его, модель сообщила успех.
  Независимая проверка подтвердила точные 33 байта и SHA-256
  `9e09d2ae468609ed60512aea8632c8047145dd1deed5cfd76226fcb711488a16`.

Управление браузером в этих сценариях выполнял субагент `gpt-6-luna`
с ограниченным контекстом. HTTP 503 сценарий потребовал 9 вызовов sky,
46,082 секунды целиком и 32,501 секунды от отправки до результата.
Инструменты не предоставили расход токенов и стоимость отдельного субагента,
поэтому денежная экономия относительно основной модели не измерена.

Отзыв согласия проверен с управляемой задержкой ответа уже принятого чтения.
Галочка передачи снята, сеанс поставлен на паузу, ответ стенда отпущен.
Нового вложения, helper-result и следующего ответа модели не появилось.
Агент выполнил одно чтение и сохранил результат.

Chrome закрыт штатным Exit, его окна исчезли. При остановленном тестовом агенте
скопированы журнал и хранилище именно установленного расширения.
Каждый файл копии проверен по SHA-256. В прежнюю папку расширения распакован
совместимый комплект `c77f022`, запущен его готовый EXE с прежними корнями и
журналом. После запуска Chrome результат появился в панели с прежним ID,
размером 35 байт и хешем. Старый EXE также вернул `completed` по прежнему ключу.
Тестовый HTTP-посредник затем остановлен, возвращён прямой EXE `9810165`.

Продолжение выявило две ошибки восстановления. Приостановленная передача
возвращалась в `attaching_files` без нового исполнителя после перезагрузки
скрипта. Сохранённый ID вкладки также мог устареть после перезапуска Chrome.
Исправления `aae9cff` и `deba937` повторно подключают скрипт, проверяют историю,
сверяют адрес и маркер перед сменой ID вкладки, сохраняют файл при ошибке.
Проверка неопределённой доставки выполняется отдельным действием чтения.
Тесты включают заменённый ID вкладки, чужой адрес, чужой маркер, переиспользованный
ID, отсутствие страницы и оба результата проверки доставки. Вызовов инструмента
и автоматической повторной передачи в этих сценариях нет.

Старое неопределённое состояние после отката завершено ручной передачей
сохранённого файла и точного helper-result через штатный UI. Нового вызова
агента не было. Это ручное восстановление старой операции.

Заключительная проверка обычного автоматического режима выполнена на
исправленном коде `29b8780`. Все три флажка передачи, автопередачи и вложений
включены. Один новый обычный запрос прочитал `written-321a6b1.txt`.
Плагин сам выполнил чтение, прикрепил файл, нажал Run и подтвердил доставку.
Модель вернула все три строки с буквальными обратными слешами и кавычками.
Панель перешла в «сеанс готов», ожидающий вызов и поле результата очистились.
Ручных кнопок плагина после отправки этого запроса не нажимали.
Журнал подтверждает одно чтение для этого цикла. Весь файл содержит 50 байт,
его SHA-256 совпадает с проверенным выше. Запросов исправления формата — ноль.

При проверке также устранены оставшийся v1 recoverTurn перед новым v2-запросом,
преждевременное снятие владения черновиком перед Run и чтение подписи вложения
вместе со служебным JSON. Подтверждение доставки теперь читает один точный
источник кода пользовательского сообщения и исключает содержимое файловых
превью. Дублирующиеся источники отклоняются.

Чистая сборка `29b8780` прошла 356 обязательных тестов без пропусков,
включая 91 сценарий реального Chrome, EXE агента и регрессии Gate.
Последующие изменения локального выпуска ограничиваются этим отчётом
и инструкциями установки, перед публикацией выполняется повторная полная сборка.
Этап 12 с резервным Gate получает отдельную реализацию и живую приёмку.
